**Evidence-Guided, Process-Constrained Self-Healing Telemetry Pipeline**  
*Developed for the HorizonXT-PS8 Hackathon*

## 1. Project Purpose

In mission-critical industrial manufacturing (boilers, pumps, gas turbines, compressors), sensor telemetry is vulnerable to harsh operating conditions, electrical transients, calibration creep, communication drops, and ADC hardware stalls. 

**FusionHeal** is an intelligent, real-time industrial data-quality gateway designed to sit directly between data acquisition sources (field gateways, microcontrollers, MQTT brokers, OPC UA servers, or simulators) and downstream supervisory control, predictive maintenance, and analytics platforms.

Its core responsibilities are:
1. **Acquire Telemetry**: Ingest real-time sensor streams over HTTP REST endpoints or adapters.
2. **Validate Records**: Enforce Pydantic schemas, strict UTC timezone normalization, monotonic sequence integrity, and physical boundaries.
3. **Preserve Original Observations**: Store immutable raw sensor payloads before applying any transformation or repair.
4. **Detect Data-Quality Issues**: Identify missing values, missing messages/intervals, communication stalls, frozen sensors, sudden rate-of-change spikes, gradual calibration drift, and malformed signals.
5. **Pluggable ML Inference Interface**: Provide an abstract, decoupled bridge for spatial-temporal Transformer imputation models (developed by ML teammates) without fabricating predictions when models are offline.
6. **Constrain & Validate Candidates**: Subject all reconstruction candidates to physical process safety bounds, rate-of-change envelopes, and confidence policy thresholds.
7. **Assign Explicit 4-Status Decisions**: Classify every observation into the four official decision statuses:
   - `PRESERVE`: Retains original raw measurement unchanged when clean or valid.
   - `REPAIR`: Replaces corrupted value with validated candidate strictly meeting physical acceptance policies.
   - `REVIEW`: Flags event for domain operator assessment when evidence is borderline or requires investigation.
   - `UNRESOLVED`: Preserves original value when reliable correction cannot be established.
8. **Operator Review Workflow**: Provide API and dashboard interfaces for retrieving pending reviews (`GET /api/reviews`) and recording auditable operator transitions (`POST /api/events/{event_id}/review`).
9. **Cryptographic Provenance & Audit Logging**: Generate append-oriented, SHA-256 cryptographically chained audit trails preserving every decision reason, actor, status transition, rule version, and model version.
10. **Expose Real-Time APIs**: Deliver filtered readings, events, reviews, operational overviews, audit histories, and benchmark metrics for dashboard monitoring.
11. **Quantitative Evaluation & 3-Way Baselines**: Benchmark the complete pipeline against fault-injected ground truth and compare against Baseline 1 (No-Repair) and Baseline 2 (Linear Interpolation).

## 4. Standardized Sensor Record Schema

Every received observation conforms to the canonical typed contract:

```json
{
  "reading_id": "RD-000001",
  "asset_id": "boiler_01",
  "sensor_id": "temperature_01",
  "event_timestamp": "2026-10-27T04:18:30.000Z",
  "sequence_number": 1001,
  "value": 72.5,
  "unit": "C",
  "source_type": "simulated"
}
```

### Field Definitions

| Field | Type | Description | Rules & Constraints |
| :--- | :--- | :--- | :--- |
| `reading_id` | `string` | Unique identifier for observation | UUID or unique serial ID. Ingestion handles duplicates idempotently. |
| `asset_id` | `string` | Industrial asset identifier | Example: `boiler_01` or `pump_01`. |
| `sensor_id` | `string` | Specific sensor instrument | Example: `temperature_01` or `vibration_01`. |
| `event_timestamp` | `ISO 8601` | When physical measurement occurred | Timezone-aware timestamp normalized to UTC. Ambient timezone offsets are converted to UTC. (Accepts `timestamp` for backward compatibility). |
| `sequence_number` | `integer` | Monotonic stream counter | Tracked per sensor stream to detect packet drops, gaps, and regressive out-of-order frames. |
| `value` | `float \| null` | Physical measurement | `null` represents explicit missing data. Non-finite values (`NaN`, `Infinity`, `-Infinity`) are rejected. |
| `unit` | `string` | Engineering measurement unit | Validated against configured sensor profile (`C`, `m/s2`). |
| `source_type` | `string` | Origin vocabulary | Controlled vocabulary: `"simulated"` or `"physical"`. All current simulator records use `"simulated"`. |

## 5. Timestamp Conventions

FusionHeal enforces strict UTC timestamp standards and maintains three distinct, non-conflated timestamps for every observation:

1. **`event_timestamp`**: The physical or simulated instant the measurement took place. Never silently overwritten with receipt time.
2. **`received_at`**: The precise UTC timestamp when the FusionHeal ingestion gateway accepted the HTTP or adapter frame.
3. **`processed_at`**: The UTC timestamp when pipeline validation, detection, decision processing, and audit persistence concluded.

### Ingestion Delay vs. Processing Latency
* **Ingestion Delay**: $\Delta t_{\text{ingest}} = \text{received\_at} - \text{event\_timestamp}$ (Measures network transmission lag or gateway delay).
* **Processing Latency**: $\Delta t_{\text{proc}} = \text{processed\_at} - \text{received\_at}$ (Measures pipeline internal compute overhead).
* **End-to-End Latency**: $\Delta t_{\text{e2e}} = \text{processed\_at} - \text{event\_timestamp}$.

## 6. Data-Quality & Decision Status Taxonomy

FusionHeal maintains a clear separation between **quality assessment** and **actionable decisions**:

### A. Data-Quality Status (`quality_status`)
Describes the diagnostic health of the incoming observation or affected interval:
* **`VALID`**: Reading passes all physical, sequence, and rate-of-change rules.
* **`SUSPECT`**: Non-fatal anomaly detected (e.g. rate-of-change spike, CUSUM drift, or repeated identical values requiring contextual confirmation).
* **`MISSING`**: Explicit null reading (`value=null`) or missing message interval.
* **`INVALID`**: Gross physical plausibility breach, malformed schema, corrupted unit, or non-finite number.

### B. Decision Status (`decision_status`)
Strict 3-status industrial decision taxonomy:
* **`PRESERVE`**: The observation conforms to all applicable rules. Original reading is preserved intact.
* **`REPAIR`**: A data-quality issue was identified; a valid reconstruction candidate was proposed by the ML interface; the candidate passes all hard physical bounds and dynamic rate-of-change constraints; the candidate was verified against auto-acceptance policy.
* **`UNRESOLVED`**: The ML model is disconnected or produced no candidate; the proposed candidate violated physical bounds; uncertainty exceeded configured policy; or operator review is required to distinguish legitimate steady-state operation from sensor failure. **The system refuses to fabricate replacement numbers.**

## 8. Pluggable ML Transformer Integration

Our teammate is developing the spatial-temporal Transformer model (e.g., SAITS or ImTransformer) independently.

### The Decoupled Abstraction: `ReconstructionModel`
All ML inference is abstracted behind [`app/pipeline/reconstruction.py`](file:///c:/Users/suhai/OneDrive/Desktop/FusionHeal/app/pipeline/reconstruction.py):

```python
from app.pipeline.reconstruction import ReconstructionModel, ModelPrediction

class SpatialTemporalTransformerAdapter(ReconstructionModel):
    def __init__(self, model_weights_path: str):
        import onnxruntime as ort
        self.session = ort.InferenceSession(model_weights_path)
        self.version = "1.0.0-saits"

    def predict(self, asset_id: str, sensor_id: str, sensor_window: list[dict], target_timestamp=None) -> ModelPrediction:
        # 1. Format tensor from sensor_window: [Batch, Window_Size, Channels]
        # 2. Run inference: point estimate + uncertainty prediction interval
        return ModelPrediction(
            available=True,
            candidate_value=73.5,
            uncertainty_lower=72.0,
            uncertainty_upper=75.0,
            confidence_score=0.92,
            model_name="SAITSTransformer",
            model_version=self.version,
            reconstruction_method="saits_attention",
            notes="Prediction interval width within tolerance.",
        )
```

### Safety Guarantees:
* **No Score Fabrication**: When the model is disconnected (`PlaceholderReconstructionAdapter`), `confidence_score` is `null` and `model_version` is `"unavailable"`.
* **Zero Raw Data Loss**: If the ML model throws an unhandled exception or OOM error, `safe_predict()` catches the error, marks the inference as `ERROR`, and logs an `UNRESOLVED` decision without losing the raw observation.
* **Physical Constraint Veto**: The `DecisionEngine` independently checks every candidate against physical limits (e.g. boiler temperature $\le 150^\circ\text{C}$). High ML confidence can **never** override physical constraint violations.

## 12. Known Limitations & Assumptions

1. **Current Data Source is Simulated**: Physical microcontrollers are not currently connected. All telemetry is generated by `SyntheticSensorGenerator`.
2. **Pending Transformer Weights**: The spatial-temporal Transformer is being trained by our ML teammate. The pipeline is running with `PlaceholderReconstructionAdapter` which safely marks candidates as `UNRESOLVED` rather than fabricating fake predictions.
3. **Storage Engine**: SQLite is utilized for hackathon zero-config execution. SQLAlchemy models are structured with strict types and indexes for immediate migration to PostgreSQL or TimescaleDB.
4. **Audit Immutability**: Cryptographic SHA-256 hash chaining detects database tampering, but hardware-level WORM (Write Once Read Many) storage or external ledger timestamping is assumed for certified SOC 2 compliance.
